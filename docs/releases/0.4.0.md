# v0.4.0

게임을 브라우저에서 직접 돌리고, 점수는 서버가 입력 기록을 처음부터 다시 돌려 검증하는 구조로 바꿨습니다. 혼자 하는 게임이라 Reloader 처럼 모든 반응에 지연이 없고, 점수 · 순위는 조작할 수 없게 지킵니다.

## 달라진 점

- **지연 없음.** 쏘기 · 총소리 · 반동 · 맞기 · 적의 반응 · 총 걸림까지 모두 내 컴퓨터에서 바로 계산합니다 (전에는 서버를 다녀와야 했습니다).
- **연결이 끊겨도 판이 이어집니다.** 판 도중에는 서버와 연결하지 않습니다. 시작할 때 판 토큰을 받고, 끝날 때 기록을 올립니다. 시작할 때 서버에 닿지 않으면 플레이는 하되 그 판의 점수는 기록되지 않는다고 알립니다.
- **일시정지.** Esc 나 P 로 멈추고, 다른 탭으로 가거나 창이 가려지면 저절로 멈춥니다. 아무 키나(또는 클릭) 누르면 이어지고, 이어지게 한 키는 게임 입력으로 쓰지 않습니다.
- **점수 검증.** 판을 끝내면 서버가 기록을 다시 돌려 계산한 "검증된 점수"를 보여 주고, 최고 점수는 검증된 점수로만 남깁니다.
- 총이 바쁠 때(쏜 직후) 누른 쏘기는, 나중에 나가도 누른 순간 겨눈 방향으로 나갑니다.

## 내부 변경

- **구조**: 실시간 WebSocket 과 서버의 30Hz 게임 루프, 화면의 예측 · 보정(`predict.ts`, `gunpredict.ts`)을 없앴습니다. 서버는 화면 파일과 API 두 개만 서빙합니다.
  - `POST /api/run/start`: 서버가 시드를 정하고 `{판 번호, 시드, 시작 시각}` 에 HMAC 으로 서명한 판 토큰을 줍니다 (`SESSION_SECRET`, Render 가 만들어 유지).
  - `POST /api/run/finish`: 판 토큰(`X-Run-Token` 헤더)과 입력 기록을 받아, 같은 시드로 처음부터 다시 돌려 점수를 직접 계산합니다. 화면이 보낸 점수 · 상태는 쓰지 않습니다.
- **결정성** (`src/shared/dmath.ts`): 브라우저 엔진마다 마지막 자리 결과가 다를 수 있는 `Math.sin · cos · atan2 · hypot` 대신, 사칙연산과 `Math.sqrt` 만으로 만든 함수를 시뮬레이션에 씁니다 (Math 와의 차이 1e-9 이하).
- **판 진행기** (`src/shared/runner.ts`): 입력 처리 규칙(총이 바쁘면 쏘기 · 제압을 기다렸다 처리, 장전은 4개까지 줄 세움)을 화면과 서버가 함께 씁니다. 조준 각도는 쏠 때만 0.0001 라디안 단위로 남기고, 그 밖에는 몸 방향(오른쪽 · 왼쪽)만 남깁니다.
- **입력 기록** (`src/shared/replay.ts`): 바뀐 틱만 `[지난 틱 수, 좌우, 각도, 키 묶음, 장전 동작]` 으로 적습니다 (10분 판 ≈ 30~50KB). 기록 모양 검사, 최대 2시간.
- **검증 서버** (`server/runs.ts`, `server/index.ts`):
  - 토큰 위조 · 3시간 넘은 토큰 · 같은 판 다시 올리기 · 실제 걸린 시간보다 긴 기록을 거절합니다.
  - 본문을 읽기 전에 헤더의 토큰부터 확인하고, 본문은 1MB, 검증 대기는 4개까지(넘치면 503), 주소마다 시작 분당 20번 · 검증 분당 10번 남짓.
  - 검증(다시 돌리기)은 한 번에 하나씩, 3000틱씩 나눠 돌려 그 사이에 다른 요청을 받습니다 (2시간 판도 CPU 1개 기준 한 번에 26ms 넘게 막히지 않음).
  - 다른 사이트에서 온 요청(Origin)은 거절합니다.
- 화면의 개발 모드 전용 시험 값은 운영 빌드에 들어가지 않습니다.

## 확인한 것

- 단위 테스트: 결정적 수학의 정확도, 무작위 입력 판과 적을 쓰러뜨리고 · 쓰러지고 · 방을 넘는 4분 판에서 브라우저 판 = 서버가 다시 돌린 판(점수 · 처치 · 재시도 · 방), 이상한 기록 거절, 기록 속 점수 조작 무시, 토큰 위조 · 다시 올리기 · 실제 시간보다 긴 기록 거절, 대기 중 쏘기의 조준
- 브라우저(Playwright)로 정직하게 플레이한 판을 올리면 서버 결과가 같고, 브라우저에서 처치 · 방 · 탈출을 조작해 올리면 서버는 실제 기록대로 계산하는 것, 같은 판을 두 번 올리면 거절되는 것
- 운영 방식 서버에서 판 시작 · 플레이 · 일시정지, 다른 Origin · 가짜 토큰 거절
- 세 방향(결정성 · 보안 · 화면) 코드 리뷰와 반박 검증으로 확인된 문제를 고침
