# v0.4.1

## 달라진 점

- **판 기록 저장.** 서버가 검증한 판의 결과(점수 · 탈출 · 방 · 처치 · 재시도 · 시간 · 틱 수)와 입력 기록(gzip 압축)을 DB 에 남깁니다. 다음 단계의 리더보드가 이 기록을 씁니다. 입력 기록을 남겨 두므로 나중에 규칙이 바뀌어도 다시 검증할 수 있습니다.
- DB 에 닿지 못한 판은 결과 화면에 "검증된 점수 N (서버에 저장하지는 못했어요)" 로 알립니다.

## 고친 것

- 서버가 재시작되면(잠듦 · 배포) "이미 올린 판" 목록이 지워져 같은 판을 다시 올릴 수 있었습니다 (v0.4.0 리뷰에서 남긴 문제). 이제 판 번호를 DB 에 먼저 찜하고(`INSERT … ON CONFLICT DO NOTHING`), 이미 있으면 거절합니다.

## 내부 변경

- `server/store.ts`: 판 기록 저장소. `DATABASE_URL` 이 있으면 PostgreSQL(Neon), 없으면 메모리.
  - 표 `runs`: 판 번호(기본 키) · 시드 · 게임 버전 · 기록 형식 버전 · 시작 · 찜 · 끝 시각 · 결과 열 · `log_gz`.
  - Friday Deploy 와 같은 원칙: 만들 때 접속하지 않고 테이블은 첫 사용 때 만들며 실패하면 다음에 다시 시도, 모든 작업을 트랜잭션으로 감싸 `SET LOCAL statement_timeout` (Neon 풀링 주소 호환), 연결 2개 · 접속 10초 · 쿼리 15초 제한, 쉬던 연결이 끊겨도 서버가 죽지 않음, 매개변수 쿼리만.
- `server/runs.ts`: 검증 전에 DB 에 판 번호를 찜하고, 검증 뒤 결과를 저장합니다. DB 에 닿지 못하면 검증만 하고 `saved: false` 로 알립니다 (메모리 목록으로 같은 서버 안의 다시 올리기는 계속 막음).
- `/healthz` 에 저장소 종류(`store`)를 더했습니다.
- 작업 규칙(`CLAUDE.md`)에 "판 기록은 지우지 않는다"를 더했습니다.

## 확인한 것

- 단위 테스트: 저장소에 이미 있는 판 번호 거절(재시작 흉내), DB 에 닿지 못할 때 검증 · `saved: false`
- PostgreSQL 16 에서: 판 번호 한 번만 찜, 결과 · 압축 기록 저장과 복원, 새 저장소(재시작)에서도 거절, 접속 실패 시 reject
- 실제 서버 + PostgreSQL + 브라우저(Playwright): 플레이한 판을 올리면 저장되고, 서버를 재시작한 뒤 같은 판을 다시 올리면 "이미 올린 판"으로 거절. DB 를 끈 동안 올린 판은 검증되고 `saved: false`, 서버는 계속 응답, DB 를 다시 켜면 저장됨
