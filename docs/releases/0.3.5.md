# v0.3.5

## 달라진 점

- **장전이 바로 반응합니다.** 탄창 빼기(R) · 쥐기(1~4) · 꽂기(F) · 칸에 넣기(G) · 슬라이드(Space)가 서버의 답을 기다리지 않고 키를 누르는 즉시 총 리그에서 움직이고 소리가 납니다. 이 동작들의 결과는 화면에 이미 보이는 것(탄창이 꽂혔는지 · 칸 · 손)만으로 정해지기 때문입니다.
  - 슬라이드를 당겼을 때 무엇이 튀어나오는지(남아 있던 탄 · 걸린 탄피)는 숨긴 정보라, 서버의 답이 온 뒤에 보여 줍니다.
  - 총이 동작 중(반동 · 장전)일 때 누른 동작은 미리 보여 주지 않고, 서버가 순서대로 처리한 뒤에 보입니다.
- **방아쇠.** 클릭하는 순간 총 리그의 방아쇠가 당겨지고 딸깍 소리가 납니다. 탄이 나갔는지(총소리 · 반동 · 탄피)는 서버의 답을 기다립니다 (약실 · 걸림은 숨긴 정보).

## 고친 것

- 총을 위로 들면 아래 띠의 위쪽에서 총이 잘렸습니다. 검은 띠는 따로 그리고, 총 리그는 띠보다 높은 투명한 영역에 맨 위로 겹쳐 그립니다. 띠 위쪽의 투명한 부분으로는 맵이 그대로 보입니다.
- 총 리그 영역에 배경이 칠해져 있어 그 근처의 물체가 가려 보였습니다. 배경은 띠에만 둡니다.

## 내부 변경

- **통신 규격 5** (`PROTOCOL_VERSION` 4 → 5): 스냅샷에 실제로 처리한 마지막 장전 동작의 입력 번호(`actAck`)를 싣습니다. 입력을 받은 번호(`ack`)와 따로 두어, 총이 바빠 기다린 동작을 화면이 너무 일찍 내려놓아 되돌아가 보이지 않게 합니다. 줄이 넘쳐 버린 동작도 처리한 것으로 알립니다.
- **장전 예측** (`src/client/gunpredict.ts`): 보이는 상태에 장전 동작을 적용하는 규칙(`applyAct`, 서버의 총과 같은 결과인지 테스트), 미리 적용 · 서버에 맞추기 · 1.5초 동안 처리되지 않은 동작 내려놓기. 바쁜 시간은 화면 시계를 기준으로 하고(서버 값은 왕복만큼 늦음), 프레임이 끊겨도 실제 흐른 시간으로 줄입니다. 서버 사건 중 화면이 이미 보여 준 장전은 다시 재생하지 않습니다.
- **총 리그** (`src/client/rig.ts`): 방아쇠를 따로 떼어 움직입니다. 그리는 영역과 크기 기준(띠 높이)을 나눴습니다.

## 확인한 것

- 단위 테스트: 보이는 상태 규칙이 서버의 총과 같은 결과를 내는 것, 서버가 처리하기 전 스냅샷에도 되돌아가지 않는 것, 바쁜 동안은 미리 하지 않는 것, 처리되지 않은 동작을 내려놓는 것, 서버의 `actAck` 가 기다린 동작이 처리된 뒤에 올라가는 것
- 왕복 150ms 로 늦춘 연결(Playwright)에서 키를 누른 뒤 총 리그 상태가 바뀌기까지: 빼기 28~34ms · 쥐기 11~12ms · 꽂기 5~12ms, 서버 답이 온 뒤에도 그대로
- 운영 방식 서버에서 한글 입력 상태 키로 장전 순서, 1280×720 · 800×600 의 레터박스와 총 리그
